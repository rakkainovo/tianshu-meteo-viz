## 一、选题说明

**现实痛点**
中国气象局每天发布数百条气象预警信号，覆盖高温、暴雨、大风、大雾、寒潮、
地质灾害等十余个灾种、四个等级，分散在 2500 多个气象台站。普通公众看到的是
一条条孤立的短信推送，**无法感知"全国正在发生什么""我所在的城市风险如何演变"**；
应急管理人员也缺少一个能一眼看清全局态势、逐级下钻到具体区县的分析界面。

**本平台要解决的问题**
把分散的、文本形态的气象预警数据，转化为**可感知、可交互、可下钻的时空态势图**。

**为什么符合评分标准**

| 评分项 | 本项目的支撑 |
|---|---|
| ① 真实性和可用性 | 全部数据来自中国气象局公开接口**现场采集**，非模拟、非二手；采集脚本可复现 |
| ② 感知性和可行性 | 面（行政区划色块）+ 点（预警落区）双层空间表达；全国→省→市→区县四级下钻；七视图联动 |
| ③ 艺术性和设计性 | 深色科技风；**直接复用官方预警四色**作为地图色彩语义；动效克制 |
| ④ 原创性和有价值 | 预警文本结构化解析 + **实时增量更新引擎** + 时空回放 + 台风路径投影扩展 + 可解释的智能问答 |
| ⑤ 论文内容合理 | 完整的需求分析、总体设计、详细实现、测试章节（见 `docs/`） |

## 二、数据来源

全部通过 `crawler/` 目录下的脚本**自行采集**，来源均为公开数据：

| 数据集 | 规模 | 采集接口 | 耗时 |
|---|---|---|---|
| 全国气象站点清单 | 34 省级单位 / **2528 站点** | `nmc.cn/rest/province/*` | 8.8 s |
| 站点实况 + 7 日预报 | **2526 条**（成功率 99.9%） | `nmc.cn/rest/weather` | 7 min 19 s |
| 全国实时气象预警信号 | **208 条**（坐标匹配率 100%） | `nmc.cn/rest/findAlarm` + `weather.com.cn/api/v1/traffic/alarm/alarmMap` | 4.9 s |
| 台风路径与强度 | **28 个 / 1536 路径点** | `typhoon.nmc.cn/weatherservice/*` | 9.0 s |
| 行政区划边界（离线地图） | **365 个 GeoJSON / 26.6 MB** | 阿里 DataV 标准行政区划边界 | ~13 min |

全程 **3029 个请求 0 失败**。采集原理、反爬应对与清洗方法见
[`docs/01-数据采集指南.md`](docs/01-数据采集指南.md)。

> **预警为什么是两路源**：实测 `nmc.cn` 的 `/rest/findAlarm` 全国流**不收录青海省**
> （2026-09-17 ~ 10-02 连续 15 天 0 条，而同一时刻中国天气网挂着 3 条果洛州雷电预警），
> 属于上游平台缺口而非采集问题。因此 `crawler/weathercn_client.py` 额外接入中国气象局
> 公共气象服务中心的中国天气网接口作补充源。两路数据同出于**国家预警信息发布中心**，
> alertid 格式一致（如 `63262241600000_20261002102000`），按该主键合并去重即可，
> 不必引入第二套标识体系；`alarm` 表用 `source` 字段（`nmc` / `weathercn`）标注来源。

### 数据不止是静态快照：内置实时更新引擎

服务启动后，后台**持续**从气象局增量拉取新数据（详见
[`docs/03-实时更新机制说明.md`](docs/03-实时更新机制说明.md)）：

| 任务 | 节奏 | 说明 |
|---|---|---|
| 预警信号 | 每 60 秒 | 增量入库（按 alertid 去重），新预警最快 1 分钟内出现在大屏上 |
| 站点实况 | 每 45 秒一轮 | 最久未更新优先轮转，每轮 300 站，约 13 分钟覆盖全国 2528 站 |
| 台风路径 | 每 30 分钟 | 路径与强度全量覆盖 |

前端通过 SSE 长连接被动感知变更：顶栏有 **LIVE 实时徽标**（最后更新时间可走字），
新入库的预警打 **NEW** 徽标，所有页面保留用户状态地增量刷新；
第 7 个页面「实时引擎」把这套机制本身可视化了（任务调度、实时曲线、事件流、分省新鲜度）。

## 三、快速开始

### 方式一：一键启动（推荐）

双击 **`start.bat`** —— 会自动完成「建虚拟环境 → 装依赖 → 建数据库 → 起服务 → 开浏览器」。

### 方式二：手动启动

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
python server/db.py --stats        # 构建数据库并输出体检报告（已建库会自动原地迁移）
python server/app.py               # → http://127.0.0.1:5000（实时引擎随服务启动）
```

启动参数（可选）：`--no-live` 关闭实时引擎，只提供静态数据服务；
`--alarm-interval 60 --weather-interval 45 --weather-batch 300 --typhoon-interval 1800`
可调各任务的节奏。前端 URL 加 `?static=1` 可进入静态模式（不建立推送长连接，
适合录屏/截图）。

> 数据库与离线地图已随项目提供，**不需要重新采集**，断网也能完整运行。
>
> 唯一需要联网的环节是 `start.bat` 首次安装 Flask。若目标机器完全离线，
> 把 `.venv/` 目录一起拷贝过去即可。

### 可选：接入大模型增强问答

不配置也能完整使用（规则引擎覆盖全部问法）。若要启用通道 B：

```bat
set LLM_API_KEY=sk-xxxx
set LLM_BASE=https://api.deepseek.com/v1
set LLM_MODEL=deepseek-chat
```

### 可选：重新采集数据

```bash
cd crawler
python fetch_geo.py                                  # 补全离线地图
python run_collect.py stations alarms weather typhoon
python build_dataset.py
python ../server/db.py
```

## 五、可视化设计

### 三维气象沙盘（试用版）

导航栏「三维沙盘」或 `/?enter=1#/sandtable` 可进入新视图。Three.js 与交互依赖全部本地化，无需外部地图服务。

实时使用请打开 `http://127.0.0.1:5000/?enter=1#/sandtable`，确保服务开启实时引擎、顶栏自动刷新开启。`static=1` 专用于截图，会暂停页面自动更新；沙盘会明确提示暂停状态。成功采集轮次变化时会刷新当前生效集合，即使没有新发布的预警；详情同步更新，撤销的预警会退出当前详情。从沙盘进入预警地图会重新取数，并保留地区、等级和回放时间范围。

- 全国 → 省 → 地市的立体行政区地图；左上角返回箭头逐级回退，面包屑可直接返回上级或全国；继续点击区县会进入原有预警地图。
- 面色表示区域内最高预警等级，数量柱表示条数，点表示单条预警落区。无匹配预警的区域使用灰色。
- 今日生效只展示北京时间当天发布、且最近一次采集仍在生效的预警；态势总览的默认地图、数量和清单使用相同时间口径，不再叠加已失效背景点。历史数据保留供主动切换查看，沙盘历史回放仍按所选窗口累计发布。
- 顶部「时间范围」可直接选择最近 6 小时 / 1、3、7、15、30 天、自定义 1—365 天或全部历史，切换后先展示窗口内累计发布分布，再按需拖动、单步或变速回放（10 分钟一帧）。最近 N 天以本次读取时刻为终点，历史模式注明含已失效记录；默认仍为今日生效。同一窗口回放期间保持柱高比例固定。
- 支持灾种、等级筛选，区域排序、预警详情、图层开关、相机旋转缩放、俯视、复位与二维切换；WebGL 不可用时自动降级二维。

当前版为统计沙盘，地图厚度仅用于立体表达，不表示地形高程。柱高范围随区域、窗口或筛选变化，跨不同范围应以标注的数值比较。

### 5.2 两个关键设计决策

态势总览的「预警数量时间演化」默认展示最近 15 天（滚动 15×24 小时），可通过范围下拉框切换到「全部历史（运行以来）」。小图与放大图共用范围，支持按等级／省份对比；切换趋势展示范围不会改变地图的今日生效口径或清除地图时间筛选。

**① 色彩语义不发明，直接复用官方标准。**
中国气象局预警信号本身就是"颜色 + 等级"绑定（红 > 橙 > 黄 > 蓝）。
地图色块沿用同一套色，用户不看图例就能理解"这片区域一片红"意味着什么。

**② 面与点分层表达。**
`geo` 组件叠加 `map` 系列（`geoIndex: 0`）画行政区划色块——表达区域整体风险；
`scatter` / `effectScatter`（`coordinateSystem: 'geo'`）画预警落区——表达具体发生位置。
两者共享同一套投影，天然对齐。

## 六、智能问答

### 查询架构

```
用户提问
   ├──▶ 气象查询层：站点/地区 + 指标 + 时间 + 操作 + 会话上下文
   ├──▶ 预警、台风、时钟规则解析器
   └──▶ 大模型受控工具查询（可选，复杂问题或无法识别时触发）
                          │
                          ▼
              意图执行器：生成 SQL → 查 SQLite → 计算结论
                          │
                          ▼
              渲染器：结论文本 + ECharts option + 支撑 SQL
```

模型可调用查找站点、查询实况、逐日预报、历史观测和生效预警工具。
工具参数、查询对象、指标和时间范围由后端校验，模型不能生成或执行SQL。
核心结论和数值由后端生成，回答附有实际查询SQL、绑定参数与相关数据时间。

支持站名与平台编码精确查询、同名站选择、多轮追问、当前页面站点上下文、
实况/预报分流、气象要素对比与排名、单站历史趋势，以及原有预警统计和台风查询。
对话在当前浏览器会话内保留，可开始新对话。站点编码沿用上游平台标识，不等同于国家气象站号。

`observation_history` 按站点与真实观测发布时间去重，数据库触发器自动保存每次实况写入，
因此批量采集与按需刷新均能积累历史。迁移仅回填已有的当前/上一帧真实记录，
后台定期清理30天以前的历史；未覆盖的过去时段会明确提示，不能追溯补造。
预报仅为逐日数据，不支持小时预报；上游降水字段未标明统计时段，不能当作24小时累计雨量。

回归测试：`python tests/test_qa.py` → **21/21 通过**。

新增语义和接口测试：`python tests/test_qa_data.py`（离线运行，不调用外部模型）。
采集入库回归：`python tests/test_live_storage.py`，覆盖磁盘数据库的批量实况、
单站补采、预报写入、历史记录去重，以及系统临时目录回退到中文路径时的证书路径选择。
SQLite 连接统一通过 `server/db.py` 的 `connect()` 创建，临时表使用内存；
该配置只对当前连接生效，迁移连接设置一次不能保护后台后续的采集写入。
浏览器验证：安装 Playwright 后运行 `node tests/qa_browser.cjs`，默认使用本机 Chrome 和5188端口；
可通过 `QA_URL`、`QA_BROWSER` 指定服务地址及浏览器。覆盖桌面/移动端、同名站选择、
会话恢复、站点跳转、图表像素与控制台异常。
