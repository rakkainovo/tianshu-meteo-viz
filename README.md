## 一、选题说明

**现实痛点**
中国气象局每天发布数百条气象预警信号，覆盖高温、暴雨、大风、大雾、寒潮、
地质灾害等十余个灾种、四个等级，分散在 2500 多个气象台站。普通公众看到的是
一条条孤立的短信推送，**无法感知"全国正在发生什么""我所在的城市风险如何演变"**；
应急管理人员也缺少一个能一眼看清全局态势、逐级下钻到具体区县的分析界面。

**本平台要解决的问题**
把分散的、文本形态的气象预警数据，转化为**可感知、可交互、可下钻的时空态势图**。

**为什么符合评分标准**

| 评分项 | 本项目的支撑 |
|---|---|
| ① 真实性和可用性 | 全部数据来自中国气象局公开接口**现场采集**，非模拟、非二手；采集脚本可复现 |
| ② 感知性和可行性 | 面（行政区划色块）+ 点（预警落区）双层空间表达；全国→省→市→区县四级下钻；七视图联动 |
| ③ 艺术性和设计性 | 深色科技风；**直接复用官方预警四色**作为地图色彩语义；动效克制 |
| ④ 原创性和有价值 | 预警文本结构化解析 + **实时增量更新引擎** + 时空回放 + 台风路径投影扩展 + 可解释的智能问答 |
| ⑤ 论文内容合理 | 完整的需求分析、总体设计、详细实现、测试章节（见 `docs/`） |

### 数据不止是静态快照：内置实时更新引擎

服务启动后，后台**持续**从气象局增量拉取新数据（详见
[`docs/03-实时更新机制说明.md`](docs/03-实时更新机制说明.md)）：

| 任务 | 节奏 | 说明 |
|---|---|---|
| 预警信号 | 每 60 秒 | 增量入库（按 alertid 去重），新预警最快 1 分钟内出现在大屏上 |
| 站点实况 | 每 45 秒一轮 | 最久未更新优先轮转，每轮 300 站，约 13 分钟覆盖全国 2528 站 |
| 台风路径 | 每 30 分钟 | 路径与强度全量覆盖 |

前端通过 SSE 长连接被动感知变更：顶栏有 **LIVE 实时徽标**（最后更新时间可走字），
新入库的预警打 **NEW** 徽标，所有页面保留用户状态地增量刷新；
第 7 个页面「实时引擎」把这套机制本身可视化了（任务调度、实时曲线、事件流、分省新鲜度）。

## 三、快速开始

### 方式一：一键启动（推荐）

双击 **`start.bat`** —— 会自动完成「建虚拟环境 → 装依赖 → 建数据库 → 起服务 → 开浏览器」。

### 方式二：手动启动

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
python server/db.py --stats        # 构建数据库并输出体检报告（已建库会自动原地迁移）
python server/app.py               # → http://127.0.0.1:5000（实时引擎随服务启动）
```

启动参数（可选）：`--no-live` 关闭实时引擎，只提供静态数据服务；
`--alarm-interval 60 --weather-interval 45 --weather-batch 300 --typhoon-interval 1800`
可调各任务的节奏。前端 URL 加 `?static=1` 可进入静态模式（不建立推送长连接，
适合录屏/截图）。

> 数据库与离线地图已随项目提供，**不需要重新采集**，断网也能完整运行。
>
> 唯一需要联网的环节是 `start.bat` 首次安装 Flask。若目标机器完全离线，
> 把 `.venv/` 目录一起拷贝过去即可。

### 可选：接入大模型增强问答

不配置也能完整使用（规则引擎覆盖全部问法）。若要启用通道 B：

```bat
set LLM_API_KEY=sk-xxxx
set LLM_BASE=https://api.deepseek.com/v1
set LLM_MODEL=deepseek-chat
```

### 可选：重新采集数据

```bash
cd crawler
python fetch_geo.py                                  # 补全离线地图
python run_collect.py stations alarms weather typhoon
python build_dataset.py
python ../server/db.py
```

### 5.2 两个关键设计决策

**① 色彩语义不发明，直接复用官方标准。**
中国气象局预警信号本身就是"颜色 + 等级"绑定（红 > 橙 > 黄 > 蓝）。
地图色块沿用同一套色，用户不看图例就能理解"这片区域一片红"意味着什么。

**② 面与点分层表达。**
`geo` 组件叠加 `map` 系列（`geoIndex: 0`）画行政区划色块——表达区域整体风险；
`scatter` / `effectScatter`（`coordinateSystem: 'geo'`）画预警落区——表达具体发生位置。
两者共享同一套投影，天然对齐。

### 5.3 三级下钻与离线地图

```
全国(100000) ──点击省份──▶ 省(440000) ──点击城市──▶ 市(c440100) ──▶ 区县预警点
```

地图数据按需从 `/api/geo/<adcode>` 取，前端 `MapHub` 做注册缓存。
**365 个地图文件全部本地化**，答辩现场断网也能完整下钻。

### 5.4 交互设计汇总（对应评分项 ②）

| 交互类型 | 实现位置 | 说明 |
|---|---|---|
| 多图联动 | 预警地图 | 地图点击 → 列表过滤 → 详情卡刷新 |
| 分级下钻 | 预警地图 | 全国 → 省 → 市 → 区县，面包屑可回退 |
| 时间轴回放 | 时空回放 / 台风路径 | 静态数据获得"事件流"观感 |
| 条件过滤 | 预警地图 / 站点实况 | 灾种 × 等级 × 省份 × 关键词四维组合 |
| 自然语言查询 | 智能问答 | 第三代人机交互，且结论可溯源到 SQL |
| 阈值切换 | 时空回放 | 只看橙色以上 / 只看红色 |
| **实时推送（SSE）** | 全部页面 | 服务端数据变更主动推送，前端保留状态增量刷新；NEW 徽标 / 更新走字 / 事件流可溯源 |

## 六、智能问答

### 双通道架构

```
用户提问
   ├──▶ 通道 A：规则解析器（默认，零依赖，永远可用）
   └──▶ 通道 B：大模型解析器（可选，仅在 A 无法识别时触发）
                          │
                          ▼
              意图执行器：生成 SQL → 查 SQLite → 计算结论
                          │
                          ▼
              渲染器：结论文本 + ECharts option + 支撑 SQL
```

**模型不接触原始数据、不做算术**，只负责把口语翻译成意图 JSON。
结论里每个数字都能追溯到一条可复现的 SQL。

支持 **15 类意图**：计数 / 省份排名 / 城市排名 / 单位排名 / 条件筛选 / 等级分布 /
灾种分布 / 时间趋势 / 地区对比 / 要素极值 / 要素排名 / 站点统计 / 天气概况 /
台风强度 / 台风路径 / 态势总结。

回归测试：`python tests/test_qa.py` → **21/21 通过**。
