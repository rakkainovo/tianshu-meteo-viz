# 数据采集完全指南 —— 从"不知道怎么采集"到"采到 2500+ 条真实数据"

> 本文档既是本项目的技术说明，也是课程论文「数据采集」章节的写作素材。
> 配套代码：`crawler/` 目录。

---

## 一、先建立一个正确的认知

"自己采集数据"听起来很玄，其实**只有四种路数**。任何一个网页的数据，都逃不出这四种：

| 路数 | 适用场景 | 难度 | 本项目是否使用 |
|---|---|---|---|
| **① 调用公开 API / JSON 接口** | 网站前端也是靠这种接口拿数据的 | ⭐ | ✅ 主力方法 |
| **② 解析 HTML 页面** | 数据直接写在网页标签里 | ⭐⭐ | ✅ 辅助 |
| **③ 下载公开数据文件** | 官网提供 CSV / Excel / ZIP | ⭐ | ✅ 补充 |
| **④ 浏览器自动化（Selenium/Playwright）** | 数据要点击、滚动、登录才出现 | ⭐⭐⭐⭐ | ❌ 本项目不需要 |

**核心心法：优先找 ①，实在找不到再退到 ②，最后才动 ④。**
因为 ④ 慢、脆、容易被封，能不用就不用。

## 二、怎么找到隐藏的接口（这是最关键的一步）

### 2.1 打开开发者工具

1. 用 Chrome 打开目标网站，比如 `http://www.nmc.cn/publish/forecast/ASH/shanghai.html`
2. 按 **F12** 打开开发者工具
3. 切到 **Network（网络）** 面板
4. 勾选 **Fetch/XHR** 过滤器
5. 按 **F5 刷新页面**
6. 观察列表里新增的请求 —— **网页上显示的数据就藏在这些请求的响应里**

### 2.2 辨别哪些是数据接口

点开每一个 XHR 请求，看 **Response（响应）** 标签：

- 如果是 **JSON**（一堆 `{ "key": "value" }`）→ 这就是我们要的接口 ✅
- 如果是 HTML 整页 → 不是接口，跳过
- 如果是图片/字体 → 跳过

本项目找到的关键接口：

```
GET http://www.nmc.cn/rest/province/all
      → 返回全国 34 个省级单位

GET http://www.nmc.cn/rest/province/ASH
      → 返回上海市下辖的 11 个气象站点及站点编码

GET http://www.nmc.cn/rest/weather?stationid=bwUMl
      → 返回该站点的实况 + 7 日预报 + 逐小时气温 + 气候背景

GET http://www.nmc.cn/rest/findAlarm?pageNo=1&pageSize=200
      → 返回全国正在生效的气象预警信号（分页）

GET https://forecast.weather.com.cn/api/v1/traffic/alarm/alarmMap
      → 中国天气网（气象局公共气象服务中心）的生效预警，作为**补充源**。
        该接口不收录青海省（见下），故与上一条合并使用

GET http://typhoon.nmc.cn/weatherservice/typhoon/jsons/list_default
      → 返回台风列表
GET http://typhoon.nmc.cn/weatherservice/typhoon/jsons/view_<台风ID>
      → 返回该台风的完整移动路径（经纬度序列）
```

### 2.3 记录下三件事

找到接口后，一定要在原样复制下这三样东西，缺一不可：

1. **完整 URL**（包括 `?` 后面的所有查询参数）
2. **请求头里的 `Referer`** —— 很多网站会校验这个字段，缺了就返回 403
3. **请求方法**（GET 还是 POST）

> 右键请求 → **Copy → Copy as cURL**，是一条最快的捷径，
> 能把 URL、请求头、Cookie 一次性全复制出来。

## 三、开始写代码：一个能跑的最小爬虫

### 3.1 第一版：极简版（30 行）

```python
import requests

# 1. 伪造浏览器身份。不加这个，很多网站直接返回 403
HEADERS = {
    "User-Agent": ("Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
                   "AppleWebKit/537.36 (KHTML, like Gecko) "
                   "Chrome/126.0.0.0 Safari/537.36"),
    "Referer": "http://www.nmc.cn/",
}

# 2. 发起请求
url = "http://www.nmc.cn/rest/weather"
params = {"stationid": "bwUMl"}          # 上海徐家汇站
r = requests.get(url, params=params, headers=HEADERS, timeout=20)

print(r.status_code)                     # 期望 200
data = r.json()                          # 把响应直接解析成 Python 字典

# 3. 取出想要的字段
real = data["data"]["real"]["weather"]
print("温度:", real["temperature"])
print("湿度:", real["humidity"])
print("天气:", real["info"])
```

**先把这 30 行跑通，再谈其他。** 一上来就写复杂框架，是新手最容易踩的坑。

### 3.2 遇到 403 / 412 怎么办？

这是采集中最常见的敌人。按下面顺序逐个排查：

**① 检查请求头是否齐全**
`User-Agent` 和 `Referer` 是必需的。有的网站还要求 `X-Requested-With: XMLHttpRequest`。

**② 检查是否需要 Cookie**
有些网站要求先访问一次首页拿到 Cookie，再调接口。用 `requests.Session()` 自动保持：

```python
s = requests.Session()
s.headers.update(HEADERS)
s.get("http://www.nmc.cn/", timeout=20)          # 先访问首页，拿到 Cookie
r = s.get("http://www.nmc.cn/rest/weather",
          params={"stationid": "bwUMl"}, timeout=20)   # 再调接口
```

**③ 检查是否被 TLS 指纹识别了 —— 本项目遇到的真实情况**

即使请求头完全一样，用 `requests` 访问本项目的数据接口依然会被拦。
原因是：**服务器不只检查"你说了什么"，还检查"你的加密握手长什么样"**。
Python 的 `requests` 库底层用的 TLS 握手特征和真实 Chrome 不一样，一眼就能被认出来。

解决办法是换用 `curl_cffi`，它会**完整模拟真实 Chrome 的 TLS / HTTP2 指纹**：

```bash
pip install curl_cffi
```

```python
from curl_cffi import requests as creq

s = creq.Session(impersonate="chrome124")     # 关键：模拟 Chrome 124 指纹
r = s.get("http://www.nmc.cn/rest/weather",
          params={"stationid": "bwUMl"}, timeout=20)
print(r.json())      # 成功拿到数据
```

> **这是本项目最有技术含量的一个点，论文里可以单独写一小节。**

**④ 检查是不是请求太快被限流了**
降低频率。本项目用了一个令牌桶限速器，把全局请求速率控制在 6 次/秒以内。

### 3.3 处理 JSONP 返回值

中央气象台的台风接口返回的不是纯 JSON，而是**包了一层函数调用的 JSONP**：

```
cb(({ "typhoonList": [ ... ] }))
```

处理办法是先剥壳再解析：

```python
def unwrap_jsonp(text):
    a = text.find("((")
    if a >= 0:
        return json.loads(text[a + 2:text.rfind("))")])   # 剥掉外层 cb(( ))
    a = text.find("(")
    return json.loads(text[a + 1:text.rfind(")")])
```

## 四、从"能采一条"到"能采两千条"

单条能采通，只完成了 20%。剩下 80% 是工程问题：

### 4.1 分层采集：先拿目录，再拿明细

不要一上来就想抓所有数据。像本项目这样**分两层**：

```
第一层：拿"目录"      -> /rest/province/all          34 条      (1 秒)
第二层：拿"子目录"    -> /rest/province/{省code}     2528 条     (8 秒)
第三层：拿"明细"      -> /rest/weather?stationid=x   2528 条     (~7 分钟)
```

第一层结果是第二层的**输入参数**，第二层结果是第三层的**输入参数**。
这样数据结构清晰，中途失败也能断点续传。

### 4.2 并发 + 限速：既要快，又要有礼貌

2528 个站点，一个一个顺着采要 20 多分钟。用线程池并发能压到 7 分钟。
但**不能无脑并发** —— 那是攻击行为，会被封 IP。

正确做法是 **「有限并发 + 全局限速」**：

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

with ThreadPoolExecutor(max_workers=6) as ex:      # 6 个线程并行
    futures = {ex.submit(fetch_one, sid): sid for sid in all_ids}
    for f in as_completed(futures):
        try:
            results.append(f.result())
        except Exception as e:
            failed.append((futures[f], str(e)))    # 记录失败项，不中断整体
```

关键的 **RateLimiter**（令牌桶）：

```python
class RateLimiter:
    """保证全局请求速率不超过 rate 次/秒"""
    def __init__(self, rate=6.0):
        self.min_interval = 1.0 / rate
        self._lock = threading.Lock()
        self._next_time = time.monotonic()

    def wait(self):
        with self._lock:
            now = time.monotonic()
            sleep_for = max(0.0, self._next_time - now)
            self._next_time = max(now, self._next_time) + self.min_interval
        if sleep_for > 0:
            time.sleep(sleep_for)
```

### 4.3 失败重试 + 退避

网络总会抖。每个请求失败后要重试，且**重试间隔逐次加长**（指数退避），
避免在对方服务器压力大时雪上加霜：

```python
for attempt in range(3):
    try:
        return self.session.get(url, timeout=25).json()
    except Exception as e:
        last_err = e
        time.sleep(0.5 * (attempt + 1))     # 0.5s → 1.0s → 1.5s
raise RuntimeError("三次都失败了: %s" % last_err)
```

### 4.4 线程安全：每个线程一个 Session

`requests.Session` / `curl_cffi.Session` **不是线程安全的**。
多线程共用同一个 Session 会出现"连接串味"，导致随机报错。
正确做法是用 `threading.local()` 给每个线程分配独立 Session：

```python
def __init__(self):
    self._local = threading.local()

@property
def session(self):
    s = getattr(self._local, "session", None)
    if s is None:                              # 本线程还没有，就建一个
        s = creq.Session(impersonate="chrome124")
        self._local.session = s
    return s
```

> 本项目实测：加了这一条之后，2528 个请求 **0 失败**。

## 五、数据清洗：爬下来的原始数据是"脏"的

爬虫拿到的只是"原料"，直接喂给图表是不行的。

### 5.1 非结构化字段结构化

预警接口返回的标题是一整句话，没有分开的字段：

```
"江西省吉安市遂川县气象台发布暴雨橙色预警信号"
```

需要用正则把它拆成 `发布单位 / 预警类型 / 预警等级` 三个字段：

```python
import re
ALARM_RE = re.compile(r"^(?P<issuer>.+?)发布(?P<type>.+?)(?P<level>蓝色|黄色|橙色|红色)预警信号")

m = ALARM_RE.match("江西省吉安市遂川县气象台发布暴雨橙色预警信号")
print(m.group("issuer"))   # 江西省吉安市遂川县气象台
print(m.group("type"))     # 暴雨
print(m.group("level"))    # 橙色
```

拆完之后，才能做"各类型预警数量统计""等级分布饼图"这样的可视化。

### 5.2 补充衍生字段

原始数据里的行政区划代码（`440118`）本身没有意义，但可以：
- 取前 **2 位** → 省代码（44 = 广东省）
- 取前 **4 位** → 市代码
- 取前 **6 位** → 区县代码

有了省代码，才能把预警点画到中国地图上。

### 5.3 注意脏数据

- 温度可能是 `null`（站点设备离线）
- 时间戳有毫秒和字符串两种格式
- 台风列表里有些台风没有中文名（显示为 `nameless`）
- **所有数值字段都要做 None 判断**，否则前端图表直接崩

## 六、合规与伦理（写进论文会加分）

1. **只采集公开数据**：不碰需要登录、不碰个人隐私、不碰付费内容。
2. **控制频率**：默认 6 请求/秒，不对服务器造成压力。
3. **声明来源**：所有图表和论文中都标注数据来源。
4. **非商业用途**：仅用于课程学习研究。
5. **遵守 robots.txt**：动手前先看一眼目标网站的 `robots.txt`。

## 八、常见报错速查表

| 报错 | 原因 | 解决办法 |
|---|---|---|
| `403 Forbidden` | 请求头不全 / 被 WAF 识别 | 补 `User-Agent` + `Referer`；改用 `curl_cffi` |
| `412 Precondition Failed` | 反爬风控 | 先访问首页拿 Cookie；模拟浏览器指纹 |
| `404 Not Found` | 接口路径写错或已下线 | 重新在 F12 里找当前真实接口 |
| `405 Not Allowed` | 请求方法用错 | 把 GET 换成 POST，或反之 |
| `SSLError: certificate verify failed` | 目标站点证书过期 | 加 `verify=False`（仅用于公开数据） |
| `JSONDecodeError` | 返回的不是 JSON（可能是 JSONP 或 HTML） | 先打印 `r.text` 看原始内容 |
| 全部请求随机失败 | 多线程共用 Session | 用 `threading.local()` 每线程独立 Session |
| 响应变慢 / 开始返回错误 | 被限流 | 降低并发数、调低请求速率 |
